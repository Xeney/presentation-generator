# Модели

Все модели — **open weights** с лицензией Apache 2.0 / MIT, до 35B параметров
(требование ТЗ, §3). Платные API не используются. Инференс — локально через
[Ollama](https://ollama.com) в контейнере `ollama` (см. `docker-compose.yml`).

## 1. LLM планировщика

| Параметр | Значение |
|---|---|
| Модель | **Qwen2.5-7B-Instruct** (основная), Qwen2.5-14B-Instruct (опция) |
| Роль в пайплайне | `backend/app/planner/` — бриф + контент-пакет + профиль шаблона → JSON-колода по Pydantic-схеме `Deck` |
| Лицензия | Apache 2.0 |
| Вес | 7B ≈ 4.7 ГБ (Q4_K_M), 14B ≈ 9 ГБ (Q4_K_M) |
| RAM/VRAM | 7B: от 8 ГБ RAM или 6 ГБ VRAM; 14B: от 16 ГБ RAM или 12 ГБ VRAM |
| Контекст | 32K токенов; сервис использует ≈ 4–8K (схема + бриф + корпус) |
| HuggingFace | https://huggingface.co/Qwen/Qwen2.5-7B-Instruct · https://huggingface.co/Qwen/Qwen2.5-14B-Instruct |
| Ollama | `qwen2.5:7b-instruct`, `qwen2.5:14b-instruct` |

Почему именно эта модель: сильная работа с русским языком и структурированным
выводом (JSON), стабильно держит схему с перечислениями, помещается в 8 ГБ VRAM
в квантованном виде. Переключение — переменной `LLM_MODEL`.

## 2. VLM аудита

| Параметр | Значение |
|---|---|
| Модель | **Qwen2.5-VL-7B-Instruct** |
| Роль в пайплайне | `backend/app/audit/vlm.py` — оценка PNG-рендера каждого слайда по 11 вопросам Приложения 1 ТЗ (смысл, соответствие заголовку, факты, опечатки, язык, логика соседних слайдов) |
| Лицензия | Apache 2.0 |
| Вес | ≈ 6 ГБ (Q4_K_M) |
| RAM/VRAM | от 10 ГБ RAM или 8 ГБ VRAM |
| Вход | PNG слайда (≈ 1280×720, DPI 110) + промпт `prompts/vlm/` |
| HuggingFace | https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct |
| Ollama | `qwen2.5-vl:7b-instruct` |

Свойство метода: проверки недетерминированные — на повторных запусках ответ может
отличаться. Это ожидаемо по ТЗ (Приложение 1) и отражено в `docs/AUDIT.md`.
VLM-этап — самая дорогая часть пайплайна по времени, поэтому он включается флагом
`VLM_AUDIT_ENABLED` и по умолчанию выполняется только для одного варианта вёрстки.

## 3. Эмбеддинги

| Параметр | Значение |
|---|---|
| Модель | **BGE-M3** |
| Роль в пайплайне | дедупликация слайдов (косинусная близость), grounding фактов: проверка, что числа и утверждения слайда присутствуют в контент-пакете |
| Лицензия | MIT |
| Вес | ≈ 2.3 ГБ (F16) |
| RAM/VRAM | от 4 ГБ RAM или 2 ГБ VRAM |
| HuggingFace | https://huggingface.co/BAAI/bge-m3 |
| Ollama | `bge-m3` (`/api/embed`) |

Модель многоязычная (в том числе русский), даёт плотные эмбеддинги 1024
размерности, не требует instruction-префиксов и работает локально без GPU.

## 4. Text-to-image (задача со звёздочкой, опционально)

ТЗ (§2.3) выделяет генерацию изображений внутри слайда как задачу для топ-10
команд: модель класса text-to-image до 20B. Требование — Apache 2.0 / MIT.

Кандидаты (решение принимается по остатку времени и ресурсов):

| Модель | Параметры | Лицензия | Комментарий |
|---|---|---|---|
| **FLUX.1-schnell** | 12B | Apache 2.0 | быстрая (1–4 шага), влезает в 16 ГБ VRAM в квантованном виде |
| **Sana** | 0.6–4.8B | Apache 2.0 | очень быстрая, низкие требования к VRAM |
| **Qwen-Image** | 20B | Apache 2.0 | лучшее качество текста на изображении, выше требования |

Текущий статус: слот `Block.kind = "image"` в схеме и в рендере есть, картинка
встраивается нативно через `add_picture` с сохранением пропорций. Источник
картинки — контент-пакет (изображения из PPTX) либо, при наличии ресурсов,
локальная text-to-image модель. Обоснование отказа/внедрения фиксируется в
`docs/DECISIONS.md` (ADR-011).

## 5. Сводные требования

| Сценарий | Минимум | Рекомендуется |
|---|---|---|
| Генерация без VLM (7B, CPU) | 8 ГБ RAM, 4 ядра | 16 ГБ RAM, 8 ядер |
| Генерация без VLM (7B, GPU) | 8 ГБ VRAM | 12 ГБ VRAM |
| Генерация + VLM | 16 ГБ RAM / 10 ГБ VRAM | 24 ГБ RAM / 16 ГБ VRAM |
| + эмбеддинги BGE-M3 | +2 ГБ VRAM | — |
| + text-to-image | +12 ГБ VRAM | +16 ГБ VRAM |

Оценка времени на колоду 10–15 слайдов: планирование 20–60 с (7B, GPU),
рендер 3 вариантов 10–25 с, детерминированный аудит 1–3 с, VLM 30–90 с,
PDF-экспорт 5–15 с. Итог укладывается в бюджет 5 минут ТЗ; замеры —
в `docs/DECISIONS.md` (ADR-012).

## 6. Внешний шлюз (режим разработки, не для сдачи)

Когда под рукой нет GPU или Ollama, сервис умеет работать с любым
**OpenAI-совместимым** шлюзом. Включается переменной `LLM_PROVIDER=openai_compat`
и адресом `OPENAI_COMPAT_BASE_URL`; ключ читается только из `.env` и никогда не
попадает в репозиторий, логи и тексты ошибок (ADR-019).

| Переменная | Назначение |
|---|---|
| `OPENAI_COMPAT_BASE_URL` | база шлюза, например `https://opencode.ai/zen/v1` |
| `OPENAI_COMPAT_API_KEY` | ключ доступа (только в `.env`) |
| `OPENAI_COMPAT_MODEL` | модель планировщика |
| `OPENAI_COMPAT_VLM_MODEL` | модель для VLM-аудита (должна уметь изображения) |
| `OPENAI_COMPAT_EMBEDDING_MODEL` | эмбеддинги; если пусто — используется локальная BGE-M3, а без Ollama grounding проверяет только числа |

Проверка настройки: `python tools/llm_check.py --json-call` — печатает провайдера,
наличие ключа (без значения), список моделей и результат крошечного JSON-запроса.

**Важно для сдачи.** ТЗ требует модели с открытыми весами до 35B и запрещает
платные API, поэтому в зачётной конфигурации используется `LLM_PROVIDER=ollama`
(Qwen2.5 + Qwen2.5-VL + BGE-M3). Внешний шлюз — только инструмент разработки:
он позволяет проверять пайплайн без GPU. Если шлюз отвечает отказом, задание не
падает: планировщик автоматически уходит в офлайн-режим, а в отчёте видно
«планировщик: офлайн-fallback».

Замер на ключе OpenCode Zen (2026-09-23, `tools/llm_check.py`): ключ валиден,
шлюз отвечает, доступно 46 моделей; бесплатные модели возвращают
`403 FreeTierError` («free tier can only be used from within OpenCode»), платные —
`402 Insufficient account funds`. То есть без баланса внешний провайдер не даёт
генерации, и сервис работает на офлайн-планировщике.

## 7. Почему Ollama

* единый локальный runtime для LLM, VLM и эмбеддингов — один контейнер, один
  порт, одна переменная окружения;
* квантованные веса и автоматический выбор GPU/CPU;
* отсутствие сетевых зависимостей и платных ключей: требование ТЗ «инференс
  самостоятельно, без платных API» выполняется по умолчанию.

Альтернативы (vLLM, llama.cpp, TGI) отклонены: избыточны для 7B-моделей и
усложняют воспроизводимый `docker compose up`.
