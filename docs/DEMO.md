# Демо и питч: ровно 7 минут

Структура по ТЗ (§4): проблема → подход → архитектура пайплайна → живое демо →
архитектура аудита → выводы и метрики. Тайминг ниже — посекундный, проверен
тремя прогонами `tools/demo_rehearsal.py` (58.1 / 58.3 / 69.5 с из бюджета
420 с: запас более чем двукратный).

## 0. Подготовка (до выхода на сцену)

```bash
cp .env.example .env
docker compose up --build          # первая сборка 4–9 мин, модели ~12 ГБ
curl http://localhost:8000/api/health   # llm.available = true
```

Чек-лист:

- [ ] `data/external_templates/` — незнакомый шаблон, которого команда не видела
      (в прогонах: Slidesgo «Anatomy Lesson», MIT).
- [ ] `data/templates/` — контент-пакет с фактами (в прогонах: пакет VK Tech,
      54 слайда, 6 цифр).
- [ ] Браузер на http://localhost:3000, окно на весь экран, зум 100 %.
- [ ] Второй таб: http://localhost:8000/docs (вопросы про API).
- [ ] Бриф в буфере обмена (текст ниже).
- [ ] Проверены провайдеры: `python tools/llm_check.py --json-call` и `--vlm`.
- [ ] Один прогон сделан заранее — кэш миниатюр тёплый, второй идёт быстрее.
- [ ] Репетиция уложилась в бюджет: `python tools/demo_rehearsal.py`.
- [ ] Таймер на 7:00 на видном месте.

Бриф для демо:

> Платформа внутренней аналитики: за квартал время подготовки отчётов
> сократилось на 40 %, автоматизированы 12 рутинных задач, охват — 5
> подразделений. Платформой пользуются 2000 сотрудников еженедельно. План —
> подключить 10 отделов к концу года, внедрить ML-предсказания выручки.

## 1. Посекундный сценарий

| Время | Блок | Что говорим и что на экране |
|---|---|---|
| 0:00–0:45 | **Проблема** | «Каждую неделю в компании рождаются десятки презентаций. Автор пишет текст, дальше — ручная работа: подобрать макет, подвинуть блоки, перекрасить диаграмму в корпоративный цвет. Модели научились писать содержание и совершенно не умеют воспроизводить дизайн-систему: они не читают чужой шаблон как набор правил». На экране — схема «текст → дизайнер → шаблон → правки». |
| 0:45–1:45 | **Подход** | «Три решения. Первое: шаблон — это данные, а не код: разбираем файл в JSON-профиль (тема, макеты, палитра, шрифты, шкала, сетка, фирменные элементы). Второе: роли макетов выводятся из структуры, имя — только подсказка, поэтому шаблон с макетами `Slide 1…N` работает. Третье: всё локально и на открытых весах — Qwen2.5, Qwen2.5-VL, BGE-M3 через Ollama, ни одного платного вызова». |
| 1:45–3:00 | **Архитектура пайплайна** | Схема `docs/ARCHITECTURE.md`: «Слои общаются только через контракты: парсинг → JSON-профиль, генерация → Pydantic-схема колоды, вёрстка → план виджетов, рендер → нативные объекты PPTX, аудит → проблемы с координатами, экспорт → PPTX/PDF/HTML. Вёрстка не читает PPTX, рендер не ходит в модель, аудит не меняет колоду — поэтому каждый слой тестируется отдельно. 173 теста, сквозной прогон `scripts/e2e.sh`». |
| 3:00–4:30 | **Живое демо** | Браузер: загрузка незнакомого шаблона (10 с) → контент-пакет (10 с) → запуск (10 с) → три варианта compact/cards/split (30 с) → аудит с красными рамками (20 с) → авто-фиксы (10 с). Генерация занимает 40–70 с: пока идёт, рассказываем, что происходит в стадиях. |
| 4:30–5:30 | **Архитектура аудита** | Таблица слоёв (ниже): «Детерминированный слой — 24 кода: геометрия, наложения, обрезка текста, кегли по шкале шаблона, цвета, контраст WCAG, плотность, таблицы, диаграммы, заглушки, дубли. Контекстуальный — VLM по 11 вопросам ТЗ с заголовками соседей. Опора на источник — BGE-M3: числа против контент-пакета и семантическая близость. Каждая проблема — код, серьёзность, слайд, текст и координаты для подсветки». |
| 5:30–7:00 | **Выводы и метрики** | «Сервис читает произвольный шаблон, собирает колоду, верстает три варианта нативными объектами, аудитирует и исправляет, экспортирует PPTX/PDF/HTML. 173 теста; матрица 8 шаблонов × 3 варианта — ноль ошибок, 21 из 24 комбинаций полностью чистые; демо-прогон 58 с из 420; рендер трёх вариантов 2–3 с. Дальше: text-to-image, параллельный VLM, дообучение планировщика на корпоративных брифах». |

## 2. План Б на каждый риск

| Риск | Что делаем | Почему сработает |
|---|---|---|
| VLM-стадия тормозит или падает | в панели отчёта переключить `vlm: off` и «применить» (`POST /api/provider`) | стадия выключается на лету; детерминированный аудит и grounding работают полностью, прогон сокращается до ~110 с |
| Внешний шлюз (AITUNNEL) недоступен | переключить провайдера на `ollama` тем же селектором (модели уже скачаны в volume) или `offline` | офлайн-планировщик собирает валидную колоду без модели, в отчёте честно `offline-fallback` |
| Модель отвечает медленно на CPU | оставить как есть: планирование уходит в офлайн-fallback через 120 с (`OLLAMA_TIMEOUT_S`), генерация завершается за ~135 с | сервис не падает и не зависает, стадии видны в отчёте |
| Docker не поднялся на сцене | `./start.sh --local` (uvicorn + next dev, без Docker) | локальный запуск описан в `docs/README.md` §6; нужны Python 3.11 и LibreOffice |
| LibreOffice не отдаёт PDF/миниатюры | показать PPTX и HTML (PDF вернётся 503 с пояснением) | презентация и экспорт PPTX не зависят от LibreOffice |
| Генерация не успела к слайду | открыть заранее прогнанное задание в `data/jobs/` и показать результат | задания переживают рестарт (ADR-016), миниатюры закэшированы |
| Незнакомый шаблон не загрузился | взять второй из `data/external_templates/` (три независимых шаблона) | матрица прогонов уже проверена на всех трёх |
| Вопрос «а если цифры выдуманы?» | показать grounding-замечания и `docs/AUDIT.md` | числа сверяются с контент-пакетом, близость считается эмбеддингами |

## 5. Запись видео

Требование ТЗ — видео ≤7:00 с аудио. Запись делает человек (экран + микрофон),
поэтому в репозитории подготовлено всё, что нужно:

1. Посекундный сценарий (§1) и план Б (§2) — можно читать с листа.
2. Три успешных прогона с хронометражем (§3) — сценарий проверен, в бюджет
   укладывается с запасом.
3. Питч-колода, собранная сервисом (§4) — её показываем на экране.
4. Команды для записи:

```bash
# сервис и прогрев
docker compose up --build -d
python tools/llm_check.py --json-call && python tools/llm_check.py --vlm

# прогон под запись (выводит хронометраж стадий)
python tools/demo_rehearsal.py \
  --template data/external_templates/PowerTemplates_Anatomy-Lesson.pptx \
  --corpus "data/templates/VK Tech шаблон.pptx" --budget 420
```

Рекомендация по записи: один дубль на весь сценарий, без склеек; если
VLM-стадия в дубле тормозит — план Б (`vlm: off`) применяется прямо в кадре и
это честно комментируется.

## 6. Ответы на вероятные вопросы

* «Как выбирается макет?» → `role`/`kind`/`score` в профиле, ADR-010 и ADR-025.
* «Почему аудит детерминированный?» → `docs/AUDIT.md`, 24 кода, один файл —
  один результат; авто-фиксы поверх (ADR-007).
* «Что с неизвестным шаблоном?» → `tools/audit_matrix.py --layouts`,
  мутированный шаблон `unfamiliar_mutated`, ADR-021.
* «Сколько стоит?» → 0 ₽ на инференс: открытые веса локально (ADR-001).
* «Что дальше?» → text-to-image (ADR-011), параллельный VLM, дообучение.
