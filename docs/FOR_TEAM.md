# Для команды: как выглядит интерфейс и что делать на защите

Короткая шпаргалка на 5 минут перед выступлением. Полные детали — в
`docs/ARCHITECTURE.md`, `docs/DEMO.md`, `docs/QUALITY.md`.

## 1. Как выглядит интерфейс (версия 2.1)

Один экран, без вкладок и переходов (ADR-030). Тёмная тема (угольные панели,
кислотный акцент, моно-лейблы), крупный шрифт. Форма — две колонки: слева
карточка **«Я не знаю, что делать»**, справа — шаги, запуск и под кнопкой
всегда раскрытый блок **«Для опытных»** (ADR-040).

**Простой режим «Я не знаю, что делать».** Нажатие одной кнопки фиксирует
безопасный набор: спрашивает **ключ внешнего сервиса** (секция «Подключите
нейросеть»), включает сборку **через HTML+CSS**, форматы **PPTX + PDF** и
проверку нейросетью; шаг 3 скрыт и заменён чипами. Без ключа генерация уходит
в офлайн-планировщик — об этом честно написано под полем.

**Форма (ручной режим).** Заголовок «Генератор презентаций». Три шага:

1. «Загрузите шаблон (файл .pptx)» — большая кнопка с иконкой папки, работает
   и перетаскивание. После загрузки видно имя файла и зелёную галочку.
2. «Опишите, о чём презентация» — большое поле с примером-подсказкой.
   Ниже — «Прикрепить файл с фактами и цифрами» (опционально).
3. «Выберите формат скачивания» — переключатели `PPTX` и `PDF`, оба включены;
   ниже способ сборки (классический / HTML+CSS / оба).

Одна акцентная кнопка «Создать презентацию». В всегда раскрытом «Для опытных»:
источник нейросети (локально/внешний и ключ), «Проверка качества нейросетью»,
число слайдов, язык и скрытая галерея примеров (открывается только на защите).

**Прогресс.** Крупные стадии «Читаем шаблон… → Пишем содержание… → Верстаем…
→ Проверяем качество…», таймер «Прошло X секунд, обычно 40–90» и «Отменить».

**Результат — секции.** Слева «Варианты оформления»: «Компактный»
(с бейджем «Рекомендуем»), «Карточками», «С данными отдельно». В каждой:
иконка, описание и кнопки «Скачать PPTX» (главная, с размером файла)
и «Скачать PDF» (вторичная). Под вариантами — блок «Проверка качества»:
цветная плашка статуса («Всё чисто» / «Хорошо, есть мелкие замечания» /
«Есть замечания» / «Есть критичные проблемы»), сводка «Проверено 29 правил
вёрстки и 11 смысловых вопросов», секции «Исправлено автоматически»,
«Требует вашего решения» (карточки «Подробнее» + «Показать, где это» — PNG
слайда с красной рамкой) и «Смысловые замечания нейросети» (список свёрнут).
Коды проверок — только в подсказке при наведении, технические жаргонизмы на
экран не выносятся. Справа — липкая колонка: «Скачать всё (ZIP)» с числом
файлов и весом, «Создать ещё раз» и «Итоги» (слайды, время, способ сборки,
нейросеть).

На экране нет превью слайдов и встроенных PDF-просмотрщиков; скачивание —
только по клику (ADR-033).

## 2. Что показывать на защите (сценарий на 7 минут)

Посекундный сценарий — `docs/DEMO.md` §1. Короткая версия:

1. Перетащить незнакомый шаблон (в прогонах: Slidesgo, MIT).
2. Вставить бриф, прикрепить контент-пакет VK Tech.
3. Нажать «Создать презентацию»; пока идёт — рассказать про стадии.
4. На результате открыть один PPTX (редактируемые объекты), скачать ZIP.
5. Прокрутить «Проверку качества» и показать «Показать, где это».
6. Если VLM тормозит — снять галочку в «Для опытных» (план Б).
7. Если отвалился внешний шлюз — «Удалить ключ / Вернуться к локальному».

## 4. Частые вопросы на защите

* **Шаблон незнакомый, имена макетов `Slide N`?** Роли выводятся из структуры,
  имя — только подсказка; проверено мутацией шаблона (`unfamiliar_mutated`).
* **А если текст не видно на тёмном фоне?** Фон считается по факту: заливка
  фигуры → декор → `p:bg` макета; проверка `text_invisible` ловит <3:1, а
  рендер заранее выбирает светлый/тёмный текст (ADR-034).
* **Почему аудит не по кнопке?** Он часть прогона: детерминированные фиксы
  применяются сразу, в отчёте видно, что сделано и что осталось (ADR-032).
* **Где ключ внешнего сервиса?** Только в памяти процесса; не в логах, не в
  ответах, не в `job.json` (ADR-031). Перезапуск — ключ вводится заново.
* **Нет LibreOffice?** PPTX скачивается всегда, PDF даёт понятное сообщение,
  карточка показывает «PDF недоступен» и подсказку скачать PPTX.
* **Почему не только HTML?** HTML не зачитывается ТЗ как результат: нужен
  PPTX, который открывается в PowerPoint и остаётся редактируемым. Поэтому
  HTML — второй рендерер поверх **того же** widget-плана, а из HTML собирается
  PPTX **нативными фигурами** (текст, таблицы, диаграммы, шевроны), без
  растрового слайда (ADR-035/036). Оба PPTX проходят один и тот же аудит:
  `audit_matrix.py --html` — 48/48 чисто.
* **Чем HTML-путь отличается от классики?** Тем же контентом и геометрией, но
  вёрстка проходит через CSS: HTML удобно открыть в браузере и напечатать в
  PDF, а конвертер переносит её в нативные объекты PPTX. На защите показываем
  оба файла рядом и HTML в браузере.
* **Сколько стоит?** 0 ₽ на инференс: открытые веса локально (ADR-001).

## 5. Перед выступлением

```bash
docker compose up --build -d
curl http://localhost:8000/api/health          # status ok
python tools/audit_matrix.py                   # 24/24 чисто
pytest backend/tests/test_dark_template.py -q  # тёмный шаблон
```

Проверить глазами три итоговых PPTX (VK WorkSpace / Education / Tech) из
`data/output/9variants_final/` — в них не должно быть невидимого текста и
шума «0 / 0 / 0». Автоматически: `python tools/check_visibility.py <deck> <template>`.
