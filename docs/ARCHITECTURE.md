# Архитектура

## 1. Задача и границы

Сервис читает **чужой PPTX-шаблон** как набор правил дизайн-системы и собирает по
нему новую презентацию из текстового брифа. Ключевое требование ТЗ: решение не
заточено под конкретные шаблоны — ни одного знания о бренде, именах макетов или
фирменных цветах в коде нет.

Пайплайн разбит на пять слоёв с односторонними зависимостями:

```
                    ┌──────────────────────────────────────────────────────────┐
  PPTX-шаблон ─────▶│ 1. ПАРСИНГ      template/parser.py → TemplateProfile     │
  бриф/контент-пакет│ 2. ГЕНЕРАЦИЯ    planner/         → Deck (Pydantic)       │
                    │ 3. ВЁРСТКА      layout/          → план виджетов         │
                    │ 4. РЕНДЕР       render/          → PPTX (нативные объекты)│
                    │ 5. АУДИТ        audit/           → Issue[]               │
                    └───────────────┬──────────────────────────────────────────┘
                                    ▼
                     экспорт: .pptx  .pdf (LibreOffice)  .html
```

Правило зависимостей: слой знает только о слоях **слева** и о JSON-контрактах.
`layout/` не читает PPTX-байты, `render/` не ходит в LLM, `audit/` не мутирует
колоду, `export/` не знает про шаблон больше, чем токены дизайна.

## 2. Слои

### 2.1 Парсинг — `backend/app/template/`

| Файл | Ответственность |
|---|---|
| `parser.py` | `TemplateParser`: тема (цвета/шрифты), мастера и макеты с геометрией плейсхолдеров, реальные слайды, палитра по частоте, типографическая шкала, сетка/поля, паттерны композиции, роль макета |
| `profile.py` | датаклассы профиля: `TemplateProfile`, `LayoutProfile`, `PlaceholderInfo`, `ColorToken`, `FontToken` |

Выход — **JSON-профиль** (`template_profiles/*.json`), который дальше читают
планировщик (объём контента), вёрстка (токены и сетка) и аудит (разрешённые
значения). Профиль — единственный мост между «чужим файлом» и остальным сервисом.

Роль макета выводится из **структуры плейсхолдеров** (тип, количество, геометрия),
имя макета используется только как tie-breaker (ADR-010).

### 2.2 Генерация — `backend/app/planner/`

| Файл | Ответственность |
|---|---|
| `planner.py` | оркестрация: промпты из `prompts/planner/`, вызов LLM, валидация ответа по Pydantic-схеме, ретраи с обратной связью об ошибках валидации |
| `llm.py` | `OllamaClient`: `/api/generate`, `/api/embed`, health-check, извлечение JSON из ответа |
| `fallback.py` | офлайн-планировщик: собирает валидную колоду из брифа без модели (dev, CI, отказ LLM) |

Контракт — `Deck` в `backend/app/models/deck.py`: строгая Pydantic-схема
(перечисления типов слайдов, блоков, диаграмм, лимиты полей). Она одновременно
является описанием для LLM, валидатором ответа и внутренним представлением.

### 2.3 Вёрстка — `backend/app/layout/`

| Файл | Ответственность |
|---|---|
| `engine.py` | `DesignContext` (токены) + `LayoutEngine.compose(slide, canvas)` → список виджетов `{widget, rect, block, style}`; три варианта: `compact`, `cards`, `split` |
| `geometry.py` | `Rect`, оценка числа строк и высоты текста, подбор кегля из шкалы, сетки и распределение высот |

Оси различий вариантов (обоснование — ADR-003):

| Вариант | Ось | Что делает |
|---|---|---|
| `compact` | плотность | полосы во всю ширину, минимальные отступы, порядок блоков сохраняется |
| `cards` | группировка | контент раскладывается в карточки-сетку 2×N |
| `split` | порядок + визуализация | данные (таблицы/диаграммы) поднимаются в отдельную колонку и рендерятся иначе |

### 2.4 Рендер — `backend/app/render/`

| Файл | Ответственность |
|---|---|
| `pptx_renderer.py` | создаёт слайды **на макетах шаблона**, кладёт заголовок в title-плейсхолдер, рисует виджеты нативными объектами: текстбоксы, автофигуры, таблицы, диаграммы (python-pptx chart), картинки; удаляет исходные слайды шаблона |
| `images.py` | пиксельные утилиты: конвертация цветов, кроп с сохранением пропорций, доминирующий цвет, наложение красных рамок проблем |
| `pdf.py` | `pptx_to_pdf` (LibreOffice headless), `pptx_to_pngs` (PDF → PNG через PyMuPDF) |

Жёсткие правила рендера:
1. слайд целиком растровой картинкой — запрещён (проверяется аудитом);
2. шрифты, цвета и кегли берутся только из профиля шаблона;
3. `add_picture` сохраняет соотношение сторон (вписывание с кропом, не растяжение).

### 2.5 Аудит — `backend/app/audit/`

| Файл | Ответственность |
|---|---|
| `checks.py` | детерминированные проверки по файлу: геометрия, наложения, обрезка, токены, контраст WCAG, плотность, заглушки, дубли, растровый слайд |
| `vlm.py` | недетерминированные проверки: рендер слайда в PNG → Qwen2.5-VL по 11 вопросам ТЗ |

Результат — список `Issue {code, severity, slide, message, bbox}`, где `bbox`
нормализован (0..1) и используется UI для красных рамок. Аудит **читает**
артефакт и колоду, но не изменяет их.

### 2.6 Экспорт — `backend/app/export/`

`html.py` собирает автономную HTML-презентацию (слайд = секция, стрелки,
клавиатура) из той же `Deck` и токенов профиля — единый контент-контракт с PPTX.
PDF получается из PPTX через LibreOffice, поэтому визуально совпадает.

## 3. Оркестрация и API

`backend/app/pipeline.py` — тонкая склейка слоёв без бизнес-логики:

```
build_profile → plan_deck → render_variants(×3) → audit_variant(×3) → audit_vlm → html_export
```

`backend/app/api/main.py` — FastAPI: приём шаблона и брифа, фоновый воркер
задания, отдача артефактов, миниатюры, аудит, авто-фиксы. Задание асинхронное,
UI опрашивает статус.

## 4. Данные и хранилище

```
data/
  templates/    загруженные шаблоны и контент-пакеты (вне git)
  jobs/         состояние заданий (переживает рестарт)
  cache/thumbs/ кэш миниатюр по хэшу PPTX
  e2e_out/      артефакты сквозных прогонов
```

## 5. Точки расширения

| Что | Где добавлять |
|---|---|
| новая проверка аудита | `audit/checks.py` — метод `_check_*`, регистрация в `audit()` |
| новое правило авто-фикса | `audit/fixes.py` — обработчик по `Issue.code` |
| новый тип блока | `models/deck.py` (`Block.kind`) → `layout/engine.py` (раскладка) → `render/pptx_renderer.py` (`_draw_item`) → `export/html.py` |
| новый вариант вёрстки | словарь `VARIANTS` + функция-компоновщик в `layout/engine.py` |
| новая модель/промпт | `prompts/<agent>/` + запись в `prompts/registry.json` |
| новый формат экспорта | `export/<format>.py`, подключение в API |
